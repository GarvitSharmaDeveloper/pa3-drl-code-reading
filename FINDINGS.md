# DRL Code Reading Findings

## TD3 Findings
While inspecting the implementation of Twin Delayed DDPG (TD3) in Stable-Baselines3, the core algorithmic mechanism largely adhered faithfully to the original paper's description. The clipped double Q-learning target, action noise bounding, and delayed policy updates are transparently implemented exactly as defined by Fujimoto et al. However, a highly surprising and consequential undocumented extension lies in the way target networks copy their running statistics for batch normalization. During the delayed polyak averaging updates (where `tau` is typically 0.005), the implementation explicitly executes a hard copy (`tau = 1.0`) of the `running_mean` and `running_var` parameters for batch normalization states from the primary networks to the target networks. The original TD3 paper does not mention using batch normalization or specifically how the internal momentum variables of batch norm should be handled across delayed target networks. Handling running statistics improperly often leads to catastrophic forgetting or delayed convergence in Actor-Critic methods. By silently forcing an absolute copy of these statistics independently of the standard polyak weight averaging, SB3 introduces a critical numerical stability fix that essentially dictates how batch normalized TD3 networks function in practice.

## PPO Findings
The Proximal Policy Optimization (PPO) implementation contained several divergences and undocumented extensions relative to the original 2017 paper by Schulman et al. The most surprising paper-divergence was the architectural topology. The PPO paper explicitly highlights parameter sharing as a structural core, stating that they use a neural network with "parameters shared between the policy and value network" and separate branches for the output heads. In sharp contrast, SB3's default `MlpPolicy` utilizes a completely disjoint architecture; the features extractor simply flattens the input, and the actor and critic are given distinct, unshared MLPs (by default `[64, 64]`). Parameter sharing is a highly consequential design choice because it heavily intertwines policy and value gradients, functionally acting as a regularizer and drastically shaping latent representations. In addition to this, the SB3 implementation performs advantage normalization per-minibatch during the PPO optimization loop instead of across the entire rollout buffer, which introduces hidden batch-size dependencies and skews gradient directions. 

## Reflection on DRL Implementation Gaps
This exercise powerfully illustrates the profound gap between the theoretical abstractions published in Deep Reinforcement Learning literature and the rugged realities of production implementations. Papers are typically incentivized to present elegant, highly simplified causal mechanisms for algorithmic improvements to maximize readability and theoretical soundness. Production codebases like Stable-Baselines3, however, exist to guarantee convergence across an unpredictable array of environments and user configurations. Consequently, production code acts as an unwritten repository of "lore" consisting of crucial numerical stability fixes (like early-stopping KL divergence constraints), architectural safeguards (like isolated MLP streams to avoid destructive interference between actor and critic), and hidden regularizations (like value-function clipping). These implementation details are rarely academic footnotes; in many cases, they govern whether the algorithm actually learns or catastrophically collapses. Without engaging in close code reading, researchers can easily fall victim to "implementation misalignment," where they attribute empirical success strictly to algorithmic theory while remaining completely unaware that the heavy lifting is actually being performed by silent engineering tricks and undocumented extensions embedded in the codebase.
